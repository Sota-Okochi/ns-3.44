## 主な結果

固定検証seed 1011〜1015、各seedのcycle 2〜5のH平均をさらに5seedで平均。
reward=H_after、episode return=sum(H_after)（4ステップ）。

|累計episode|検証平均H|
|---:|---:|
|0|0.334642561|
|64|0.337336730|
|128|0.352089434|
|192|0.320294377|
|256|0.314832895|
|320|0.309439581|
|384|0.338223323|
|448|0.352574557|
|512|0.356786665|

512は384比+5.488%、128比+1.334%、0比+6.617%。448→512は+1.195%。
512−128の対応あり差の平均は+0.004697、参考95% t区間（df=4）は
[-0.011005, 0.020400]。5seedかつ同じ検証集合でモデル選択しているため、
この区間は記述的な参考値であり、独立した最終性能の証明ではない。
モデルseedは1つ。環境seed別では128→512で3改善・2低下、448→512で2改善・3低下。

最新学習64件のH平均は0.346345、直前64件は0.354981。
学習環境seedが異なるため、これだけで方策悪化とは判断しない。

512の不満足端末数は62.55/80（78.19%）、128は62.90、384は63.10。
ログの不満足数は空欄のためS<1として再計算。
切り替えは512で200.6回/episode（4決定、50.15台/決定）、128は201.8、384は195.2。
非切り替え端末でSが低下した数は512で15.30台/cycle（因果的な切り替え被害とは限らない）。
512・448の検証RTT重視端末でtimeoutは0、384は平均0.6台/cycle。
タイムアウトが解消したと一般化はできない。

## 方策・更新の解釈

検証平均行動確率(AP0/AP1/AP2):
- 128: 42.47/28.73/28.80%
- 256: 61.14/22.37/16.50%
- 384: 46.79/31.53/21.67%
- 448: 43.33/31.20/25.47%
- 512: 38.43/33.58/27.99%

AP0への偏りが緩み検証性能も回復しているが、因果関係は未確定。
512の同一状態内UE間確率SDの平均は0.003913（384は0.008699）。
検証の全1600 UE行動で最大確率はAP0。argmax評価への変更は未検証であり勧めない。
確率的分散が改善した可能性はあるが、端末別選択を学べたとはまだ言えない。

最新16更新のclip fractionは全て0。KLは約1.39e-5〜5.14e-4で有限。
512のtraining entropy=1.08930、3選択一様分布はlog(3)=1.09861。
Critic EV before/after=0.8380/0.9097（学習バッチ内、方策の汎化性能とは別）。
明白な数値発散はない。clip fraction=0を更新停止と解釈しない。
entropy正則化が改善の主因かは未検証。今この継続runでは係数変更をしない。

## 継続提案

時間的余裕があるなら、条件を変えず640まで続けることを推奨。
448・512で最良を更新し、追加学習の効果を調べる価値がある。
512時点で2048環境遷移・64更新、640で2560遷移・80更新。
576を中間点、640を評価区切りとする。640以上は無条件に延長しない。

640後に128/512/640を未使用の共通環境seed（例:20〜30種類）で比較。
同じ初期状態・容量イベントの切り替えなし／ランダムbaselineを含める。
状態非依存の固定確率割り当ても比較できると、端末状態を使う価値を切り分けられる。
検証と最終testは分離し、可能なら行動乱数・モデルseedも別途評価。

新512 runのlatestとbestはどちらもcompleted_episodes=512、updates=64。
latest内部メタデータから再構築したexperiment_idは保存IDと一致。
修復用setting.jsonとの一致、現在のPython/Torchとソースの一致も確認。
元の設定terminals=100はそのまま保ち、実行時--terminals 80で上書きする。
最新runの実際の学習設定128件は全て80台。
再開には512run/latest.ptとresults/marl/resume384_repaired/setting.jsonを使用。
今回は再修復不要。学習中はコード・設定を変更しない。

最新128件＋検証10件の所要時間188197秒=52.28時間。
追加128件の時間は同程度の約52時間を目安とするが、実行環境に依存する。
