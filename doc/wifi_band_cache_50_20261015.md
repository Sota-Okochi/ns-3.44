# 帯域レイアウト→干渉管理データの対応再利用

## 実装

対象はInterferenceHelper::AppendEventの帯域検索のみ。
RxPowerWattPerChannelBandの不変共有レイアウトを読み取り可能にし、各InterferenceHelperが
直近1レイアウトと、ソート順に対応したBandStatesのiterator列を保持する。
同じレイアウトなら帯域ごとのm_niChanges.findを行わず列を順に参照する。
レイアウトが違えば全帯域を従来のfindで解決して列を作り直す。キャッシュは1件に限定。
共有所有権を保持し、レイアウトの解放後のアドレス再利用による誤ヒットを防ぐ。

- AddBand/RemoveBand/DoDisposeの冒頭でキャッシュを無効化する。
- UpdateBandsは変更対象についてAddBand/RemoveBandを呼ぶので無効化される。
  キー集合が変わらない場合は既存iteratorが有効なので維持する。
- 干渉履歴内部の挿入・削除は帯域mapのノードを変更しないため参照を維持できる。
- キャッシュは受信機ごとに保持し、異なる受信機間でiteratorを共有しない。
- 時刻検索、同時刻の挿入順、電力加算順、受信イベント、RNGは変更しない。

## ビルドと回帰テスト

InterferenceHelperのサイズが変わるため、3ファイルだけでなくWi-Fiモデルの158ファイルを
独立再コンパイルした。通常buildおよび比較元の共有ライブラリは上書きしていない。

```
python3 results/perf/wifi_band_cache_50_20261015/build.py
python3 -m unittest discover -s tests -p test_wifi_band_cache.py
```

テスト対象:
- 同一レイアウト反復、同じキーの別レイアウト、部分集合への切替。
- 帯域削除・再追加、UpdateBandsによる変更/全削除、Dispose。
- 複数受信機が同じレイアウトを使用しても独立したiteratorを保持。
- 実際のAppendEvent、同時刻/ゼロ長イベント、干渉履歴全体と基準電力の旧版一致。
- 小規模2seedの受信bytes/イベント数/デバイスカウンタ一致、計測ON/OFF一致。

## 50端末の1回比較

保存先: `results/perf/wifi_band_cache_50_20261015/`
比較元: `results/perf/wifi_append_parts_50_20261015/`
seed384/modelseed1/未学習モデル/動的容量/episode45/1worker/5周期。
終了後summary.txt/comparison.json/timing_comparison.jsonを生成する。
50端末での結果一致と時間短縮は完了後に判断する。学習更新なし。

今回のband_lookupはキャッシュ列参照、layout_lookupは受信単位のキャッシュ確認/再構築。
前版のband_findと名前・範囲が異なるので単一行だけを比較しない。
総時間は計測オーバーヘッド込み・単一seedの結果。最終判断には計測なし比較も必要。

実施結果: 独立ビルド成功、上記unittest 2件成功（内部で2seed比較と帯域ライフサイクル・
時系列履歴回帰を実施）、git diff --check成功。テスト用旧ヘッダのinclude経路を修正して
再実行した最終結果がtest.log。50端末の1回実行を開始済み。完了結果はまだ未確認。

## 完了後分析

comparison.jsonはcompleted、観測/遷移/QoEのバイト一致、境界イベント数一致が全てtrue。
実時間2805.561→2631.766秒（46分46秒→43分52秒）、173.794秒・約6.19%減。
Simulator::Run 2805.044→2631.004秒（6.20%減）。Wi-Fi StartRx 984.982→833.965秒
（15.33%減）。未変更のNR伝搬は460.868→453.195秒（1.66%減）。
時刻境界検索の標本値は0.563367→0.563067秒（ほぼ同じ）。
平均H=0.30179230176029526、最大RSS796376 KiB。

直前の同等計測版との単一seed比較では改善が観測された。新しい帯域対応再利用に
よる改善と整合するが、外部実行条件・計測負荷があるので純粋な効果や80端末での
改善率を断定しない。最初の50端末の粗い計測版2675.300秒と比べると約1.63%減であり、
各回の時間差を積み上げて大幅な改善と報告しない。

限界が証明されたわけではないが、以後は時刻検索・RU積分・NRチャネル計算など、
正しさ検証と実装コストの大きい変更が主体。研究スケジュールを重視するなら、
小規模最適化はここで区切り、新しい方式の80端末動作確認/学習へ進む判断が妥当。
本測定はprofile有効なので本学習では詳細計測を無効にする。ただし倍率は未測定。
