### 方策による割り当て

- 実行コマンド：`./ns3 run master -- --nth=5`。
- `./ns3 run master -- --nth=4`との違いは、APselection.cc/random_assignment()に分岐するかしないかである。
- `--nth=5`では、random_assignment()に分岐せず、新しくpolicy_assignment1()を作成してそっちに分岐する。
- policy_assignment1()の仕様
    - `master_log.csv`の「端末満足度」の部分を閲覧。
    - その端末満足度が1.0を下回っている端末を不満足端末としてカウント。
    - その不満足端末を接続切り替え対象として、今つながっている基地局とは別の基地局にランダムに割り当て結果を算出。
    - その割り当て結果をターミナルに表示、もちろん`--nth=4`と同じようにcsvに書き込む。（書き込みタイミングは`--nth=4`と同様）
    - 割り当て結果を元に、端末を切り替えて次のサイクルに移行。
    - ポイントは、`--nth=4`との違い、`--nth=5`では、policy_assignment1()に移行するだけ。その他は`--nth=4`とほぼ同じ。

### 追加で確定した仕様（ヒアリング結果）

- `--nth=5`の初期AP/初期アプリ生成は`--nth=4`と同じランダム初期化を使う。
- `policy_assignment1()`は`WriteMasterLog();`実行後に呼び出す。
- `policy_assignment1()`で参照する`master_log.csv`は、そのサイクルの行のみを対象にする。
- 端末満足度が`1.0`未満の端末のみを再割り当てし、それ以外は現在APを維持する。
- 再割り当て先APは「現在接続中AP以外の全AP」からランダム選択する。
- CSV出力のタイミングと形式は`--nth=4`と同一にする（追加フォーマットは作らない）。
- 関数名は`policy_assignment1()`で統一する。
