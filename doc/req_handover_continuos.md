# 現状
- シミュレーション時間は、7.0s。
- 10回のpingによるRTT値の取得。
- 取得した各基地局のTPとRTTを用いて割り当て前端末満足度の調和平均を計算＆出力。
- `APselection.cc`で、ランダム法によって各端末の接続先番号を算出だけ。
- 上記の流れを1サイクルとする。


# 拡張点の仕様書
## 各端末の接続先の切り替え
- ランダム法による割り当て結果を、`master/`直下にファイル（handover.cc）を作成して、その中に関数を定義。
    - 各端末の基地局先の切り替え。
    - ランダム法の結果が入った配列を受け渡し、初期配列に上書きする。
    - サイクル開始のトリガは `APselection` 側とし、ランダム割当結果を持つ `APselection` が handover 関数を呼び出して次サイクルを開始する。
    - 5GとWi-Fiをまたいだ割り当ても許容する。AP番号はNetDevice順と一致させ、ズレる場合は一致するように修正する。IPアドレスが枯渇する場合はサブネットを拡張する。 
    - ハンドオーバ時は割り当て先APのアドレス空間からIPを再割り当てし、ルーティングを再設定して整合性を取る（再設定の具体手順は実装側裁量）。

## 連続的端末満足度の調和平均の取得
- 現状のシミュレーション時間を長くする。
- 現状のプロジェクトのサイクルを2回行いたい。
    - 現状通り、7.0sで調和平均を計算＆出力（各サイクルで算出）。
    - ランダム法によって、各端末の接続先の切り替え（割り当て結果が届き次第、即時ハンドオーバ）。
    - サイクル①と同じ挙動を行い、サイクル②における端末満足度の調和平均を計算＆出力（2サイクル目はRTTとTPをリセットし、ping回数は同じ）。

### 以下はコードに反映さない点
- 今回の拡張点は、今後の拡張の基盤となるコードです。
- そのため、サイクルは2回以上になるため。
- 拡張性に適したコードを生成して。

# 追加で明確にした前提
- シミュレーション時間は2サイクル分で14.0sとする想定（7.0s×2）。
- ハンドオーバはランダム法の割り当て結果がNetSim側に渡せたタイミングですぐに実行してよい（厳密な時刻指定なし）。
- RTT/TPなどの計測値は各サイクルでリセットし、ping回数は各サイクル同じ（現状の10回）で取得する。
- ランダム割り当ては `random_assignment_test()` の既存ロジックを利用する前提。
- 5GとWi-Fiをまたいでよい。割当配列のAP番号は実際のNetDevice順と一致する前提。していない場合は一致するように修正する。IPリソース不足時はサブネット値を拡張する。
- アプリ層の継続／再起動方針は、2サイクル目が問題なく実行されることを前提に実装側で裁量を持って決定してよい。
